POWERLING PRE-AUDIT — TECHNICAL ARCHITECTURE
=============================================


OVERVIEW
--------

The Powerling Pre-Audit system automates the production of structured website audit reports for the Powerling sales team. Given a client URL (or a set of localized domain URLs) and up to three competitor URLs, the system researches each site across four analytical pillars, benchmarks the client against competitors, and delivers results in two formats depending on the audit type selected.

The system replaces a manual workflow that previously relied on SEMrush, ChatGPT, and human copy-paste, while preserving the same quality of output.


AUDIT MODES
-----------

The system supports two distinct audit types, selectable at submission time.

Auto Audit

  - Triggered immediately on submission; no approval required
  - Shorter and denser than the full report — designed for the sales team to share with prospects as a teaser
  - Delivered in-platform (web dashboard), by email, and by Microsoft Teams message
  - Target delivery: within 12 hours of submission
  - Output: in-platform 1-page summary dashboard and a downloadable condensed PDF

Human-Reviewed Audit

  - Requires approval from Nicolas before the pipeline starts
  - Full-depth report covering all pillars at maximum detail
  - Nicolas reviews and validates the output before it is released to the requester
  - Output: polished, client-ready PDF (no errors, no placeholder content)


INPUT
-----

The system accepts the following inputs submitted via a web form:

  - Client URL or URLs (one primary URL, or multiple localized domains such as .com, .fr, .de)
  - Company name (required)
  - Audit type: Auto or Human-reviewed
  - Competitor URLs, up to three
  - Extra context: free-text field for metadata, known issues, or focus areas
  - SEMrush site audit data — either via API or uploaded PDF (for Pillar 2, Website Health)

Localized Domain Handling

Corporate websites do not always use a single URL with a language dropdown. Many use localized domains or subdomains (e.g., company.com, company.fr, company.de). The system handles this by:

  - Accepting multiple URLs at submission, one per locale
  - Falling back to language switcher crawling when a single URL is provided
  - Treating each locale URL as a separate scraping target for mixed-language UX checks
  - Consolidating results into a unified language coverage analysis

Pillar 2 Data Source Options

The Website Health pillar requires crawl-level site data — broken links, hreflang conflicts, metadata coverage, redirect chains, and similar — that cannot be reliably gathered via web search alone. Three integration paths are available:

  1. DataForSEO Site Audit API (recommended) — pay-per-call, approximately $0.50–2.00 per domain, replicates SEMrush Site Audit output programmatically with no manual step required.

  2. SEMrush PDF upload — account managers run SEMrush manually and upload the PDF; the backend parses it and extracts structured data before the pipeline runs.

  3. Google PageSpeed Insights API (partial coverage) — free, no authentication required; provides performance scores and Core Web Vitals but not crawl-level data. Used as a supplement, not a standalone replacement.


SYSTEM COMPONENTS
-----------------

The system consists of three layers: a frontend web application, a backend API server, and an audit pipeline that runs in the background.

Frontend (Next.js)

The frontend provides the following pages:
  - Submission form — user enters URL(s), company name, audit type, and competitor URLs
  - Status page — polls the backend every two seconds and displays job progress
  - Summary dashboard — in-platform 1-page view of key findings (see section below)
  - Full report viewer — detailed report with all pillar content

Backend API (FastAPI)

The backend exposes a REST API for job management:
  - POST  /audits                Create a new audit job
  - POST  /audits/{id}/approve   Nicolas approves a human-review audit to start the pipeline
  - GET   /audits                List all past audit jobs
  - GET   /audits/{id}           Poll job status and metadata
  - GET   /audits/{id}/result    Retrieve the full completed report
  - GET   /audits/{id}/summary   Retrieve the condensed summary for the dashboard

On completion, the backend sends:
  - An email to the requester with the report link
  - A Microsoft Teams card with a summary and link (via Incoming Webhook)

Jobs are stored in a SQLite database with statuses: pending, awaiting approval, processing, completed, or error.


AUDIT PIPELINE
--------------

The pipeline runs fully sequentially in five phases.


Phase 1 — Deterministic Scraping

A headless browser (Playwright) and a lightweight HTTP client (requests + BeautifulSoup) collect data that requires actual page rendering:

  - Navigate to each locale-specific URL or page (EN, DE, ES variants) and check whether untranslated strings appear in calls-to-action, news cards, or navigation — detecting mixed-language UX issues
  - Fetch page source and parse hreflang tags to detect missing or conflicting international SEO signals
  - Handle localized domains (.com, .fr, .de) as separate scraping targets and consolidate results
  - Check for skip links, cookie consent banners, and keyboard navigation support
  - Crawl language switcher links on competitor sites to determine accurate language counts


Phase 2 — AI-Powered Data Gathering

A stateful, three-turn conversation with gpt-4o-search-preview gathers research data for the client site. Each turn builds on the previous:

  Turn 1 — Pillar 1: Globalization
    Languages offered, language selector type, geographic presence, traffic by country, hreflang status, translation quality observations

  Turn 2 — Pillar 3: Accessibility and Compliance
    WCAG conformance level claimed, accessibility statement presence, cookie consent implementation, privacy policy, terms of service, sitemap

  Turn 3 — Pillar 4: Online Reputation
    Social media follower counts (LinkedIn, X, Instagram, Facebook, YouTube), review platform scores (Trustpilot, Google, Glassdoor, G2/Capterra), CEO approval rating, recent news and overall sentiment

A separate single call is made for each competitor to gather all benchmark dimensions in one shot.


Phase 3 — Website Health Data (Pillar 2)

Site-wide crawl data is retrieved from either the DataForSEO Site Audit API or a parsed SEMrush PDF:
  - Total pages crawled, total errors, total warnings
  - Broken internal links count
  - Hreflang conflicts and language-region mismatches
  - Pages missing meta descriptions
  - Pages with duplicate H1 tags
  - Redirect chains and unminified asset counts

Google PageSpeed Insights provides additional per-page metrics:
  - Performance, SEO, Accessibility, and Best Practices scores
  - Core Web Vitals: Largest Contentful Paint, Cumulative Layout Shift, Interaction to Next Paint


Phase 4 — Facts Pack Assembly

All gathered data is merged into a single structured data object. The Language Coverage Rate (LCR) is computed deterministically for the client and each competitor:

  LCR = (Available Languages / Required Languages) x 100

  Score 1/3: LCR at or below 50%
  Score 2/3: LCR between 51% and 75%
  Score 3/3: LCR above 75%

Required languages are estimated based on the company's geographic footprint and active markets.


Phase 5 — Report Generation

Using the facts pack as input, gpt-4o generates each section of the report sequentially. Each section is a pure writing task with no web search — the model works only from the researched data.

Sections generated:
  1. Pillar 1: Globalization
  2. Pillar 2: Website Health
  3. Pillar 3: Accessibility and Compliance
  4. Pillar 4: Online Reputation
  5. Competitive Landscape — cross-pillar benchmark table (client vs. three competitors)
  6. Conclusion — top recommendations across all pillars and combined ROI estimate

Each pillar section contains:
  - An introductory sentence
  - Key findings overview paragraph
  - Five to seven key finding bullets
  - Impact paragraph explaining business consequences
  - Five prioritized recommendations
  - Expected ROI paragraph with estimates
  - Benchmark table comparing client to competitors on that pillar's metrics

A condensed summary is also derived from the full report for the dashboard view.


IN-PLATFORM SUMMARY DASHBOARD
------------------------------

The summary dashboard is a single-page view designed to communicate the most important findings at a glance. It is the primary output for the Auto audit format, and serves as a preview layer for the Human-reviewed audit. The design has flexibility — the goal is dense, actionable information using charts, tables, and bullet points.

Dashboard sections and components:

  Header
    Company name, URL, generation date, audit type badge, Download PDF button, Share button

  Pillar Score Cards (one per pillar)
    Visual gauge or color-coded badge showing Score 1/3, 2/3, or 3/3 for each pillar.
    Pillars: Globalization, Website Health, Accessibility, Online Reputation.

  Language Coverage Chart
    Horizontal bar chart showing covered languages (filled) and missing recommended languages (empty). Allows the prospect to immediately see the gap.

  Competitor Benchmark Table
    Grid comparing the client against up to three competitors across all four pillars. Color-coded cells (red / yellow / green) for quick visual comparison.

  Website Health Snapshot
    Key numbers displayed inline: broken links count, hreflang conflicts, missing meta descriptions, performance score, SEO score, accessibility score.

  Social and Review Score Strip
    Platform logo plus follower count or review score for LinkedIn, Trustpilot, Google, Glassdoor, and other available platforms.

  Top Recommendations
    Numbered bullet list, maximum five items, pulled from the conclusion section. Plain language, one sentence per recommendation.

  Combined ROI Estimate
    Single highlighted paragraph with estimated traffic, conversion, and lead volume uplift ranges.


OUTPUT
------

Auto Audit:
  Full report JSON stored in database
       |
       v
  Summary JSON derived from full report
       |
       ├── In-platform summary dashboard (charts, tables, bullets)
       ├── Condensed PDF (auto-generated)
       ├── Email notification to requester with report link
       └── Microsoft Teams card with summary and link

Human-Reviewed Audit:
  Full report JSON stored in database
       |
       v
  Nicolas review interface (approve, annotate, release)
       |
       v
  Polished full PDF (client-ready, no errors)
       |
       └── Email notification to requester after Nicolas approves


TECH STACK
----------

  Frontend:              Next.js 16 (App Router), TypeScript, Tailwind CSS
  Charts / visuals:      Recharts or Chart.js
  Backend API:           FastAPI (Python)
  Job persistence:       SQLite with SQLAlchemy ORM
  AI web research:       OpenAI gpt-4o-search-preview (Chat Completions)
  AI report generation:  OpenAI gpt-4o (Chat Completions, JSON mode)
  Deterministic checks:  Playwright (headless Chromium)
  Website health data:   DataForSEO Site Audit API or SEMrush PDF parser
  Performance scores:    Google PageSpeed Insights API (free)
  PDF generation:        WeasyPrint (server-side) or headless Chrome
  Email notifications:   SendGrid or SMTP
  Teams notifications:   Microsoft Teams Incoming Webhook


PILLAR SUMMARY
--------------

Pillar 1 — Globalization
  Data sources: AI web search, Playwright locale rendering
  Key metrics: Language Coverage Rate (LCR), language count, hreflang tags, mixed-language UX

Pillar 2 — Website Health
  Data sources: DataForSEO or SEMrush, Google PageSpeed Insights
  Key metrics: Broken links, crawl errors, hreflang conflicts, Core Web Vitals, performance scores

Pillar 3 — Accessibility and Compliance
  Data sources: AI web search, Playwright
  Key metrics: WCAG conformance level, accessibility statement, cookie consent, legal page coverage

Pillar 4 — Online Reputation
  Data sources: AI web search
  Key metrics: Social media followers, review scores, news sentiment, CEO approval rating
